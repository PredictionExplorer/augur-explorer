# ADR-0011: NFT art traits — ingest first, serve from the database, freeze at imprint

- Status: Accepted
- Date: 2026-08-29

## Context

Cosmic Signature art is generated by a separate repository,
[PredictionExplorer/CS-Image-Generation](https://github.com/PredictionExplorer/CS-Image-Generation).
Its `three_body_problem` pipeline renders one package per on-chain seed and
uploads it to the asset host. As of pipeline `1.0.0+traits` each package also
carries `metadata/nft_traits.json` — a per-seed trait contract — and an
`metadata/assets.json` manifest (schema_version 2) with a SHA-256 for every
file. Both are published over HTTP inside the seed's own package directory,
at `{collection}/{seed}/metadata/nft_traits.json` and
`{collection}/{seed}/metadata/assets.json`, alongside every other asset of
the package.

Until now `handleCstMetadata` served a near-empty document: a generic
description, three attributes (`Round`, `Imprinted` and a useless per-token
`seed`), and a `properties.owner`. Everything that makes the artwork
interesting — its structure, palette, spectral class, fate, chaos index, the
physics of the winning orbit, the HQ video and the 64 spectral bins — was
either uncomputable here or hosted but undiscoverable.

The upstream integration document
(`docs/augur-explorer-integration.md` in that repository) is the contract
between the two repositories. Its one rule: **anything derivable from the
seed is computed in Rust and copied verbatim here; anything from an event log
is read from the indexer; the handler only merges.**

## Decision

### Ingest into the database; never fetch on the request path

A background loop (`internal/api/cosmicgame/traits`) scans for minted seeds
whose package has not been fetched, conditionally GETs the two files, gates
them, and upserts. `handleCstMetadata` reads one row and merges. It never
contacts the asset host.

Fetching inside the request was rejected outright: it would put an external
host on the critical path of a route that marketplaces crawl in bulk, and it
would turn an asset-host outage into a metadata outage. A per-request cache
would only narrow the window, not close it.

The loop runs as a goroutine in `cmd/apiserver`, alongside the existing
contract-state refresh loops, rather than as a new binary. There is no cron
infrastructure in this repository, the work is small, and upserts are
idempotent so replicas cannot conflict.

On a cache miss the handler calls `Ingester.Nudge`, a non-blocking,
negative-cached enqueue. A token whose package landed moments ago flips to
the enriched response within seconds instead of waiting out the scan
interval, and a trending token whose package is still rendering cannot turn
page views into asset-host traffic.

### Two tables, not one

The upstream document sketches a single table. We split it:

- `cg_token_traits` — the payload. A row existing means "this seed can be
  served enriched". Its columns are exactly the art facts plus a content
  hash.
- `cg_token_traits_fetch` — ETags, attempt counts, the next-attempt schedule,
  the last status and the drift alarm.

The split buys persistent exponential backoff. Packages lag mints by minutes
to hours, so at any time a large fraction of seeds answer 404. Without a
durable schedule those thousands of seeds would be re-requested every tick
forever; with it they settle from the two-minute scan interval up to a
six-hour ceiling. It also keeps the served-data table free of operational
columns that no reader needs.

### Art facts are frozen at imprint; a diff is an incident

The generator is deterministic: re-running it for a seed reproduces identical
values. So a re-fetched trait file that disagrees with the stored row is a
determinism regression upstream, not new information.

The ingester therefore stores a `content_hash` over the canonicalized art
facts — attributes, `description_art`, `simulation`, `generation` — and on
a mismatch it **keeps the stored row**, sets `drift_detected_at` and logs at
error level. Collectors keep seeing what they already saw, and
`DriftedTraitSeeds` turns the alarm into an actionable list for the database
validation scripts.

`generated_at`, `pipeline_version` and the asset manifest are excluded from
the hash: the first is explicitly non-deterministic and the others can move
without the art changing.

### Verbatim means byte-exact

Attribute values and the `simulation`/`generation` blocks are carried as
`json.RawMessage` end to end. A JSON number decoded into `float64` and
re-encoded can change spelling, and `274.3025574565995` appearing as
`274.30255745659953` in a served document would be a silent corruption of a
published art fact. The formal schema declares `additionalProperties: false`
over the four attribute fields, so the Go struct is lossless by construction.

Blocks are canonicalized (sorted keys, no insignificant whitespace, number
literals preserved) before storage, so an identical package always produces
identical stored bytes and identical served bytes.

### The seed has two spellings

The indexer stores seeds zero-padded to 64 hex characters, because
`NftMinted` carries a `uint256`. The generator writes whatever width it was
given — the upstream fixture says `"0x100033"`. Requests use the padded form
because that is what the on-disk package directories are named, while the
seed-match gate compares after stripping the prefix and leading zeros. Both
spellings therefore resolve to one package.

### `properties.owner` is removed unconditionally

Ownership changes on every transfer while marketplaces cache metadata for
days, so a baked-in owner is permanently stale and actively misleading;
`ownerOf()` on-chain is the source of truth. The per-token `seed` attribute
goes with it: every value is unique, so it can never filter anything, and it
crowds the trait panel. The canonical seed remains in `properties.seed`.

Both are breaking changes to a frozen v1 response, taken deliberately: they
are the two fields the integration document calls out as must-fix, and the
parity goldens were regenerated in the same change.

### `metadata_version` on both shapes

The served layout is versioned independently of the trait file's
`schema_version`, starting at `2.0.0`. It is emitted on the enriched *and*
the fallback path, a small deviation from the upstream document: the layout
version is the same whether or not traits have landed, and emitting it
uniformly lets monitoring distinguish a v1 deployment from a v2 fallback.

### The schema gate refuses what it cannot interpret

Minor and patch bumps only add fields, so unknown fields are tolerated —
refusing them would strand every token behind a Go deploy. A major bump means
the layout changed: the ingester refuses the file, keeps the last good row
(or the fallback), and logs at error level.

## Consequences

- Every token serves the fallback until its package is ingested. With no
  asset host configured (`NFT_TRAITS_SOURCE_BASE` unset) that is the steady
  state, which is exactly today's behaviour minus `owner`. Rollout is
  therefore ordered Go first, generator second, backfill third, and no step
  can break the previous one.
- The metadata handler gained two small queries per request (the trait row
  and the mint source). Responses carry `Cache-Control: public, max-age=300`
  and the ETag the conditional-request middleware already computes
  (ADR-0007), so marketplace crawls revalidate cheaply.
- Both Cosmic Signature staker raffles and RandomWalk staker raffles map to
  the single `Anchored Selection` allocation. The indexer distinguishes seven
  mint sources; the collection publishes six names, because the difference
  between the two staking pools is a mechanic rather than a provenance story.
  `TestEveryMintSourceHasAnAllocation` fails if the indexer grows a prize
  family the vocabulary has not caught up with.
- Trait rows are keyed on hexadecimal seeds by database constraint. The scan
  filters non-hex seeds in SQL, so the shared test fixture's placeholder
  seeds — and any malformed production row — can never reach the tables or
  become a URL.

## Verification

- `internal/nftraits` is covered by table tests for parsing, the schema and
  seed gates, canonicalization and content hashing, plus `FuzzParse` over the
  one place this repository decodes bytes fetched from the asset host.
- The vendored upstream fixture (`internal/testfixtures/nfttraits/`) is real
  generator output. Round-trip tests assert the attributes survive
  decode/encode byte-exact, including the `Chaos` value's numeric spelling.
  When regenerating it, any diff other than `generated_at` for the same seed
  and parameters is a determinism regression to report upstream, not to
  absorb here.
- `internal/api/cosmicgame/traits` covers every fetch classification against
  an `httptest` asset host, the drift path, backoff growth and saturation,
  nudge dedupe and queue behaviour (on `testing/synctest`'s fake clock, with
  the network kept outside the bubble), and the loop's lifecycle.
- `internal/store/cosmicgame/token_traits_integration_test.go` pins the
  upsert round trip, manifest preservation across a manifest-less re-ingest,
  the scan's ordering and hex filter, attempt accumulation and the
  frozen-art guarantee at the storage layer.
- `internal/api/apitest/metadata_traits_test.go` pins the served document end
  to end for an ingested package, including attribute order, the absent owner
  and seed attribute, the fallback shape, and the allocation of every prize
  family in the fixture dataset.
